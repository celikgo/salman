# A golden capture

`conveyor.pcap` is a Modbus TCP conversation, and `conveyor.report` is what
`salman capture` says about it.

Both are **generated by salman**, from `crates/salman-analyse/tests/golden.rs`,
and the test that generates them also asserts that what is committed here is
what it would generate now. Change anything in the capture stack and the diff
appears in `conveyor.report` for a person to read before it is committed.

```
$ salman capture examples/capture/conveyor.pcap
```

## Why salman generates its own fixture

There is no small Modbus capture anywhere with clean, stateable provenance. The
Wireshark sample-capture wiki holds no Modbus captures and publishes no licence,
copyright or terms-of-use statement at all. The best-known collection
redistributes files whose upstream is undocumented, under a blanket repository
licence that cannot credibly cover third-party content — the same directory also
redistributes Modbus Organization specification PDFs, which are certainly not
under it. Several other collections carry no licence whatsoever.

So this one is salman's own, and its provenance is exactly the statement this
project's rules ask for: *generated by salman's harness, from bytes in that
test, at that commit*. It is regenerated rather than fetched, so it cannot drift
and carries nobody else's terms.

## What is in it, and why

Ten frames, each present because of a specific way a capture-based tool gets
things wrong:

| Frame | What it is | What it catches |
|---|---|---|
| 0 | A bare acknowledgement, padded to the 60-byte Ethernet minimum | Its six padding bytes read as an MBAP header of transaction 0, protocol 0, length 0. A decoder that took them as payload reports a phantom Modbus frame on every acknowledgement in every capture. |
| 1–2 | An ordinary read and its answer | The path working at all. |
| 3–4 | One request split across two TCP segments, mid-frame | A decoder fed packets rather than a reassembled stream calls this malformed. |
| 5 | Its answer | Pairing a response to a request that arrived in two pieces. |
| 6–7 | A read of an address the device does not have, and its refusal | An exception is only useful next to what was asked for, which needs the request. |
| 8 | The refusal again, byte for byte | What a SPAN or mirror port does. Counting frames rather than reassembling them double-counts every transaction. |
| 9 | A last request nothing answers | salman cannot tell "the device never answered" from "the capture stopped", and says so rather than picking one. |

## Regenerating

```
$ SALMAN_UPDATE_GOLDEN=1 cargo test -p salman-analyse --test golden
```

Read the diff before committing it. That is the whole point of a golden file.
